# 交付流水线

本 Skill 是阶段、证据、停止条件和唯一确认门禁的权威来源。外部 Skill 只能扩展阶段内职责，不得复制或改序。

## 状态与公共规则

`方案 -> 分支 -> 归档 -> 开发/代码查看 -> 测试 -> Commit -> merge origin/main -> Push -> 部署 -> 验证 -> 合并 main`

- 阶段成功后才能继续；保存命令、退出码、关键输出、文件或 commit。任一命令失败、范围越界、依据缺失或状态不明即停止。
- 唯一人工确认位于生产代码完成且 CR 通过后、测试前。展示完整 diff、架构对应、CR、测试计划、提交信息、分支/远端、部署/验证/合并计划和回滚；用户确认后，计划不变即自动执行后续阶段，包括生产部署和合并 `main`。
- 生产代码、架构、文件范围、部署目标或关键命令变化时回到代码查看；仅测试代码按既有生产契约修正无需重审。
- 用户单独要求某个后续阶段时，该请求即为该阶段授权，不重复确认。
- 先运行 `python3 scripts/delivery_check.py preflight --repo <repo>` 获取统一 Git 证据；Java 构建命令可用 `build-plan` 探测，不能覆盖仓库文档。

## 阶段要求

### 方案

明确目标、范围/非目标、现状、方案、验收、风险、依赖、回滚和关键替代方案。实质信息缺失时停止询问。

### 分支

工作区来源明确后 fetch，同步本地 `main` 到 `origin/main`，仅从最新 `main` 创建任务分支；记录基准、merge-base 和分支。禁止在 `main` 开发。

### 归档

代码前把最终方案以用户身份原文写入 folder `NhkdfHqfdloniYdNuTycU7sRndd`，标题为 `<聊天名称>之<方案名称>`；完整回读核对。新增链接按 `AGENTS.md` 登记。缺标题、权限、CLI、完整回读或一致性时停止。

### 开发与代码查看

按方案最小实现并完成生产代码 CR。向用户展示公共规则要求的完整证据；确认前不得测试。确认后生产代码变化必须重新展示。

### 测试

覆盖正常、边界、异常；先相关测试，再完整检查。任何失败禁止 Commit、Push 和部署。

### Commit

核对工作区、diff、测试和任务文件，按代码查看时列明的 Conventional Commit 自动提交；记录哈希、信息和文件。范围或计划变化时停止。

### 合并远程 main

Push/部署前 fetch，以 merge 合入最新 `origin/main`，不得 rebase。冲突时列文件并停止。代码树变化则重新测试并回到代码查看；仅空树变化的 merge commit 可自动继续。

### Push

确认开发分支已包含最新主干、验证仍有效后普通 Push；禁止 force push。远端变化或拒绝时停止。

### 部署

仅依据仓库文档/脚本，核对环境、命令、版本、风险、观测和回滚后自动执行；无可靠依据、目标变化或失败时停止，不猜测。

### 验证

按方案验收标准检查健康、接口、页面或日志，逐项记录方法与结果；任一失败不得标记完成。

### 合并 main

验证通过后 fetch，确认受测 commit、`origin/main`、保护规则和计划中的 PR/合并方式，自动完成合并与 Push。冲突、远端变化、策略不明或受测版本不一致时停止；代码树变化则重新查看、测试、部署和验证。

## 交接

报告当前阶段、证据、未完成项、风险和恢复条件。
