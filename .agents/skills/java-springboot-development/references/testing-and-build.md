# 测试与构建规范

本文件归纳手册单元测试规则，并使用 JUnit 5、Mockito 和 Spring Boot 当前测试方式。

## 单元测试

- 遵守 AIR：自动化、独立、可重复；测试不得交互，不依赖执行顺序、开发者机器或已有数据库数据。
- 测试代码位于 `src/test/java`，每个测试聚焦一个可观察行为；覆盖正常、边界和异常路径，缺陷修复先增加能复现问题的回归测试。
- 使用 JUnit 5 和项目既有断言库；测试名称表达“条件/行为/结果”，保持 Given-When-Then 或 Arrange-Act-Assert 一致。
- 单元测试不启动 Spring 上下文，不访问真实网络、数据库、文件系统、系统时钟或随机源；使用构造器注入、`Clock` 和明确接口隔离不稳定边界。
- 使用 Mockito 模拟直接协作者而非被测对象，只验证对结果重要的交互，不过度绑定实现细节。
- 测试直接调用生产代码中按大步骤拆分的流程模块，并用 mock、fake、stub、测试配置或测试夹具替换外部边界；测试与生产运行必须共享同一套业务步骤、顺序和规则。
- 禁止在 `src/test` 中复制生产方法、重写算法、拼装平行业务流程或维护“测试专用业务实现”。测试辅助代码只负责输入数据构造、外部边界替身、环境准备和断言；若生产模块难以复用，应先修正其职责或依赖边界。
- 核心业务增量必须有单元测试。覆盖率阈值采用仓库/CI 要求；若未定义，可把语句覆盖 70% 和核心逻辑更高分支覆盖作为评审参考，不以覆盖率替代断言质量。

## 集成测试

- 仅集成测试使用 Spring 上下文。Controller 切片优先 `@WebMvcTest`，持久化切片按项目选择 `@DataJpaTest`，只有跨层行为才使用 `@SpringBootTest`。
- 数据库集成测试创建自己的数据并自动清理或回滚，不操作共享开发/生产数据；需要真实数据库语义时优先使用受控容器或项目提供的隔离实例。
- 集成测试隔离外部服务，结果可重复且可并行；断言事务、唯一约束、并发更新、SQL 映射和异常转换。

## 构建识别与验证

- 优先级为 `./mvnw`、`./gradlew`、`mvn`、`gradle`；wrapper 存在但不可执行时先检查仓库约定，不擅自改权限。
- Maven：先运行相关测试，再运行 `test`，最后运行 `verify`；Gradle：先运行相关测试，再运行 `test`，最后运行 `check`。
- 对多模块项目，从覆盖改动的最小模块开始，再从仓库根运行完整检查；保留仓库定义的 profile、静态检查和安全扫描。
- 若项目配置 p3c、Checkstyle、Spotless、PMD 或其他质量插件，将其纳入完整检查；不得为了通过检查而批量格式化无关代码。
- 报告实际命令、退出码、测试数量和失败摘要。任何失败不得描述为通过，也不得继续 commit、push 或部署。
