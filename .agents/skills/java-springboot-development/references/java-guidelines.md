# Java 编程、异常与日志规范

本文件归纳《阿里巴巴 Java 开发手册（黄山版）》的编程规约与异常日志，并采用当前 JDK 的等价安全实践。

## 命名、常量与格式

- 类、接口、枚举、注解和记录使用 `UpperCamelCase`；方法、参数、字段和局部变量使用 `lowerCamelCase`；常量使用语义完整的 `UPPER_SNAKE_CASE`。
- 包名全小写、单数且每段表达一个自然语义；名称不以 `_` 或 `$` 开始或结束，不使用中英混合、拼音英语混合、侮辱性词语或难懂缩写。
- 抽象类以 `Abstract` 或 `Base` 开头，异常类以 `Exception` 结尾，测试类以被测类名开头并以 `Test` 结尾；数组声明写成 `Type[]`。
- POJO 的 `boolean` 字段不使用 `is` 前缀，避免 JavaBean/序列化歧义；枚举成员使用 `UPPER_SNAKE_CASE` 并说明业务含义。
- 消除魔法值；按业务作用域拆分常量，不建立无边界的全局常量类；有限且稳定的取值范围优先使用枚举或值对象。
- 使用 4 个空格缩进和 UTF-8/Unix 换行；禁止 Tab；单行不超过 120 字符；所有控制语句都使用大括号。
- 保持方法聚焦，建议总行数不超过 80；不同逻辑块之间使用空行，不以空格人为对齐赋值符号。

## 面向对象、类型与日期

- 覆写方法必须添加 `@Override`；通过类名访问静态成员；不得继续使用已废弃 API。
- 仅在参数类型和业务语义相同的场景使用可变参数，避免 `Object...`；对外接口或已发布库的方法签名变更必须先设计兼容方案。
- 使用常量或 `Objects.equals` 进行可空对象比较；包装类型使用 `equals`；覆盖 `equals` 时同时覆盖 `hashCode`，作为 `Set` 元素或 `Map` 键的领域对象必须保证二者一致。
- 浮点数不使用 `==` 判断等值；`BigDecimal` 使用字符串或 `valueOf` 构造并用 `compareTo` 比较。金额采用明确的最小货币单位整数或约定精度的 `BigDecimal`，不得使用二进制浮点数。
- POJO 属性不设置含混的业务默认值；序列化兼容变更保持 `serialVersionUID` 策略稳定；构造器不执行外部调用或复杂业务逻辑。
- 使用 `java.time` API；日期格式年份使用小写 `y`，区分月份 `M`、分钟 `m`、24 小时 `H` 和 12 小时 `h`；不硬编码一年为 365 天。
- 对依赖当前时间的业务注入 `Clock`；性能耗时使用单调时钟，不混用业务时间与耗时统计。

## 集合与并发

- 使用 `isEmpty()` 判断集合为空；集合转数组使用类型匹配的 `toArray`；不得修改 `Collections` 不可变返回值或 `Arrays.asList` 的结构。
- 使用 `Collectors.toMap` 时明确重复键合并策略并处理空值；不要把 `subList` 强转为 `ArrayList`，修改父子列表前评估结构共享影响。
- 不在增强 `for` 中增删元素；使用迭代器或明确的新集合。初始化可预估规模的集合并设置容量；遍历 Map 的键和值时使用 `entrySet`。
- 线程资源由边界清晰、参数显式的线程池管理；不得用 `Executors` 默认无界策略，也不得为请求随意创建裸线程。设置有意义的线程名、队列容量、拒绝策略和关闭流程。
- 单例及共享状态必须线程安全；多资源加锁保持固定顺序；竞争更新使用数据库版本、锁或其他明确并发控制，避免更新丢失。
- `ThreadLocal` 使用后必须在 `finally` 中清理；优先使用线程安全的 `DateTimeFormatter`；定时任务使用能隔离异常的调度执行器。
- 锁必须成对获取和释放，释放前确认持有；异步转同步必须保证完成信号在异常路径也能触发，并设置合理超时。

## 控制流与注释

- `switch` 的每个分支必须明确终止或标注贯穿，并提供 `default`；外部可空值进入 `switch` 前先校验。
- 避免在条件表达式中赋值或放入复杂副作用；优先提前返回处理异常分支，循环外计算不随迭代变化的值。
- 公共入口必须校验批量大小、枚举值、分页、权限边界和其他可导致资源消耗或状态错误的参数。
- 每个方法声明前必须写方法级注释并与实现同步；存在参数、返回值、异常或重要约束时使用准确的 Javadoc `@param`、`@return`、`@throws` 和必要说明。禁止只复述方法名、写“处理业务”等无信息量注释，也不得保留长期注释掉的代码。作者和日期由版本控制记录，除非仓库明确要求写入类注释。

## 业务枚举

- 业务枚举成员使用 `UPPER_SNAKE_CASE`，采用 `(数字编码, "状态说明", "注释")` 表达业务值，例如 `ENABLED(1, "启用", "允许正常处理")`。
- 注释与状态说明完全相同时允许写成 `(数字编码, "状态说明")`，由二参数构造器把注释设置为状态说明；不得保留语义相同但内容重复的第三参数。
- 数字编码必须在枚举内唯一、稳定并显式声明，不得使用 `ordinal()`、声明顺序或可变化的数据库自增值作为业务编码。
- 字段至少包含数字类型的 `code` 和字符串类型的 `statusDescription`；需要独立注释时增加 `comment`。反序列化或按编码查询时提供显式查找方法，并对未知编码执行明确的异常或兜底策略。

## 异常与日志

- 可通过预检查避免的运行时错误应先校验，不通过捕获异常控制正常流程；捕获异常必须处理、转换或继续抛出，并保留 cause。
- `finally` 负责可靠释放资源且不得 `return`；优先使用 try-with-resources。事务内捕获异常时必须确保回滚语义不被破坏。
- 区分领域异常、可恢复技术异常和编程错误，不直接抛出无语义的 `RuntimeException`，不向公共接口泄露内部堆栈。
- 统一使用 SLF4J 等日志门面和参数化占位符；禁止 `System.out`、`System.err` 和 `printStackTrace`；避免把对象整体 JSON 序列化后直接记录。
- 日志包含足以定位问题的上下文和异常堆栈，但同一异常只在负责处理的边界记录一次；按仓库策略控制级别、滚动、保留和容量。
- 不记录密码、令牌、密钥、完整个人敏感信息或未经脱敏的请求体；日志保留期必须满足适用法律和组织要求，不把手册中的固定天数当作所有项目的统一法规。

## 依赖

- 优先使用 JDK、Spring 和项目已有能力；新增依赖前确认必要性、维护状态、许可证、漏洞、版本管理和传递依赖影响。
- 不顺带升级无关依赖；通过 Maven dependency management 或 Gradle version catalog 统一仲裁版本；线上版本不得依赖不稳定快照。

## Lombok

- 先检查项目是否已经引入 Lombok、是否允许注解处理以及邻近代码的使用方式；项目未使用时，不得只为减少样板代码擅自新增依赖。
- 优先使用作用明确的 `@Getter`、`@Setter`、`@RequiredArgsConstructor`、`@Builder` 和 `@Slf4j`；避免在 Entity、领域对象或公共模型上笼统使用 `@Data`，防止意外生成 setter、`equals`、`hashCode` 和 `toString`。
- Spring 组件可以使用 `@RequiredArgsConstructor` 实现必需依赖的构造器注入；依赖字段声明为 `private final`，不得因 Lombok 改回字段注入。
- JPA Entity 仅按持久化框架要求生成无参构造器和访问器；谨慎使用 `@Builder`、`@Value`、`@EqualsAndHashCode` 和 `@ToString`，避免破坏代理、懒加载、实体身份与集合语义。
- `@EqualsAndHashCode` 必须显式考虑业务身份、可变字段和父类；继承场景明确 `callSuper`。不得让数据库生成主键在持久化前后改变集合键的哈希语义。
- `@ToString` 必须排除密码、令牌、个人敏感信息、大字段、双向关联和懒加载字段；日志中仍不得直接输出完整对象。
- 使用 `@Builder` 时明确必填字段、默认值和校验入口；字段初始化不会自动成为 Builder 默认值，需要时显式使用 `@Builder.Default`，并为构建结果补充测试。
- 禁止用 `@SneakyThrows` 隐藏受检异常契约；异常必须显式处理、转换或声明。谨慎使用 `val`、`var`、`@Cleanup` 等降低代码可读性或隐藏控制流的功能。
- 公共库、序列化模型和反射框架依赖的类必须验证生成后的 API 兼容性；必要时查看 delombok 结果。构建和 CI 必须启用一致的 Lombok 版本与注解处理，并执行编译和测试验证。
