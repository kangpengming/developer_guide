# Java Web 安全规范

本文件归纳手册安全规约；项目安全策略、适用法律和经过维护的框架安全指南优先。

## 身份、权限与敏感数据

- 所有属于用户、租户或角色的资源在服务端执行身份认证和对象级授权，不依赖前端隐藏按钮或客户端传参。
- 对展示、日志、导出和错误信息中的个人敏感数据进行最小化与脱敏；密钥、令牌和数据库密码不得提交到仓库或明文写入日志。
- 配置秘密使用受管密钥或环境注入并支持轮换；不要自行设计可逆“加密密码”方案。

## 输入与输出

- 对所有外部输入校验类型、长度、范围、格式、枚举、文件大小、文件类型和业务权限；校验失败使用稳定错误响应。
- 数据库操作使用参数绑定；动态表名、列名、排序字段等元数据必须来自服务端白名单。
- HTML 输出使用上下文正确的编码/转义并启用合适 CSP；不得输出未经处理的用户内容。
- 上传文件验证实际内容、扩展名、大小和存储路径，随机化服务端文件名，隔离执行权限，并按风险扫描。

## 请求防护

- 对使用 Cookie 身份的状态变更请求启用框架 CSRF 防护；使用其他认证方式时依据威胁模型明确等价控制。
- 外部重定向目标必须使用服务端白名单或安全映射，不直接接受任意 URL。
- 短信、邮件、支付、下单等有价值操作必须具备认证、幂等、防重放、限流和审计；令牌设置有效期并绑定业务上下文。
- 用户生成内容按业务风险实施限流、反滥用和内容安全控制；不得把简单关键词过滤视为完整安全方案。

## 失败处理

- 不向客户端泄露堆栈、SQL、内部路径、类名、依赖版本或秘密；记录可关联的事件标识供内部调查。
- 安全校验默认失败关闭；外部依赖异常、超时或解析失败时不得绕过鉴权和关键业务校验。
