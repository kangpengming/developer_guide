# 工程与设计规范

本文件归纳手册的错误码、工程结构、服务器和设计规约，并适配通用仓库。

## 错误码与契约

- 错误码必须稳定、唯一、可检索并与用户提示分离；不得包含组织架构、版本号或内部敏感信息。
- 统一维护错误码，优先复用既有分类；第三方错误转换为本系统语义，并通过日志或受控字段保留关联信息。
- 手册的固定五位编码属于一种组织方案，不强制通用模板采用；项目必须明确自己的格式、所有者和兼容策略。

## 工程与依赖

- 模块边界与依赖方向匹配业务分层；公共模块只承载稳定复用能力，不把项目杂项堆入 `common` 或 `util`。
- 先把业务流程拆成可命名的大步骤，每个大步骤由一个职责单一、输入输出明确、可独立验证的生产模块承载，再由应用层或编排器按顺序组合；不得把多个大步骤堆在单个类或长方法中。
- “一个大步骤属于一个模块”强调职责和边界，不等同于每一步都创建 Maven module、Spring Bean 或新目录；根据现有架构选择类、组件、包或实际构建模块，避免只有转发逻辑的空壳抽象。
- 流程模块通过接口隔离数据库、消息、文件、网络、时间和随机数等外部边界，使同一生产模块能在真实运行和测试环境中复用；不得为测试可用性另建一套业务流程。
- Maven 坐标和版本遵循仓库统一规则；线上制品不依赖 SNAPSHOT；同一依赖由统一位置仲裁，不在子模块声明冲突版本。
- 新增或升级依赖时比较依赖树，评估传递依赖、二进制兼容、安全漏洞、许可证和回滚；功能改动不得顺带改变无关仲裁结果。
- 发布库遵守语义化版本和兼容策略；公共 API 不返回会因新增值破坏调用方的内部枚举或实现类型。

## 远程调用与运行时

- 所有远程调用设置连接、请求和总时限，明确重试、退避、幂等、熔断、隔离及失败语义；不得无限等待或无界重试。
- 线程池、连接池、队列、缓存和请求体必须设置容量上限及可观测指标；慢依赖与核心资源隔离。
- JVM 和服务器参数以实际运行环境、容器限制和压测证据为依据，不机械套用固定 Xms/Xmx、TCP 或文件句柄值。
- 对 OOM、磁盘满、证书过期、数据库不可用和依赖超时准备监控、告警、降级与恢复方案；敏感诊断文件受控存储。

## 设计评审

- 在编码前明确目标、范围、约束、数据结构、接口契约、验收标准、风险和回滚方式；核心存储方案必须经评审并沉淀文档。
- 复杂状态变化使用状态图，跨多个参与者的调用使用时序图，复杂流程使用活动图，模型关系复杂时使用类图；简单问题不为满足形式强制画图。
- 识别强依赖和弱依赖，为弱依赖设计超时、降级、隔离和应急预案；异常路径、容量边界和数据一致性与主流程一同评审。
- 遵循单一职责、依赖倒置和开闭原则，优先组合而非继承；只提取真正稳定且多处复用的共性，避免过早抽象。
- 设计文档解释需求、关键决策、替代方案和维护方式；清晰代码不能替代系统级设计和运行说明。
