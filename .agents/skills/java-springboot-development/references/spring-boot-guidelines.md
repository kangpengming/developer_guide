# Spring Boot、接口与分层规范

本文件归纳手册中的前后端规约、应用分层和领域模型规则，并映射到现代 Spring Boot。

## 分层职责

- Controller 只处理协议适配、输入校验、认证上下文和响应映射；Service 承载业务用例、领域协调和事务；Repository 只负责持久化访问。
- 上层可以依赖下层稳定契约，下层不得反向依赖上层；避免循环依赖和为简单转发创建无意义层级。
- 使用构造器注入和不可变依赖；事务边界放在 Service，不依赖同类内部调用触发代理事务。
- DAO/Repository 层将存储异常转换为稳定的数据访问异常；Service 处理领域语义；ControllerAdvice 统一映射对外错误。

## 模型边界

- 数据库模型使用 Entity/PO，业务输入输出使用 DTO，页面或接口展示使用 VO；不得把 Entity 直接作为公共接口模型。
- 模型字段类型必须与数据库和序列化协议匹配；跨层转换应显式、可测试，不用无边界的反射复制隐藏字段差异。
- API 请求和响应字段使用 `lowerCamelCase`；超出 JavaScript 安全整数范围的标识或整数以字符串返回，并形成稳定契约。

## API 契约与错误

- 明确协议、域名、路径、HTTP 方法、请求参数、状态码、响应体、鉴权、幂等和限流要求；沿用项目既有统一响应格式。
- 空列表返回空数组或空集合而不是 `null`；限制 URL、请求体、批量操作和分页参数大小，防止异常输入耗尽资源。
- 错误响应同时使用正确 HTTP 状态码、稳定业务错误码和安全的用户消息；错误码用于定位与沟通，不直接把内部错误或堆栈展示给用户。
- 外部依赖错误应转换为本系统错误语义，同时保留可关联的原始错误信息供内部排查。
- 使用 JSON 等仓库既定格式并明确时间格式与时区；不要无条件采用手册中的固定 GMT 或路径版本策略，优先遵守已发布 API 契约。

## 校验、事务与配置

- 在入口使用 Jakarta Bean Validation，并对嵌套对象使用 `@Valid`；业务规则、权限和状态转换仍在 Service 校验。
- 更新接口区分“未提供”和“显式清空”；数据修改接口限制可更新字段，避免把整个 POJO 无差别写回数据库。
- 明确事务传播、隔离、超时和回滚条件；事务内避免不受控的慢速远程调用，并为并发、幂等、唯一性和锁设计提供测试。
- 使用 `@ConfigurationProperties` 管理成组配置并校验；地址、超时、开关和资源上限不得硬编码；密钥由受管配置注入且不得记录。
