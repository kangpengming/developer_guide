# MySQL 开发规范

本文件归纳手册的建表、索引、SQL 与 ORM 规则；先确认实际 MySQL 版本、字符集、SQL mode、规模和项目迁移机制。

## 建表与字段

- 表名和字段名使用小写 `snake_case`，不以数字开头、不使用保留字；表名使用单数并表达“业务_用途”。
- 每张业务表必须有明确主键；布尔语义字段使用项目统一的 `is_xxx` 或等价约定，并限制有效取值。
- 小数使用 `DECIMAL`，不得用 `FLOAT` 或 `DOUBLE` 存储精确数值；字符串根据实际长度选择类型，超长文本与主表访问模式分离。
- 统一 `utf8mb4` 及明确的排序规则；时间字段的类型、时区和精度必须与 Java 映射及业务语义一致。
- 业务唯一性必须由唯一约束兜底；字段含义、状态值和冗余数据必须有注释及一致性维护策略。
- 审慎采用逻辑删除。若采用，统一字段、查询过滤、唯一约束和归档策略；法律合规要求物理删除时不得以手册旧规则阻止执行。
- 不把固定的 `id/create_time/update_time` 或分库分表阈值机械套用所有表；由仓库模板和容量评审确定，并保证审计字段一致。

## 索引

- 索引服务于真实查询、排序、关联和唯一性；联合索引顺序综合等值条件、选择性、范围条件和排序要求确定。
- 字符串索引根据区分度选择合理前缀长度；避免隐式类型转换导致索引失效。
- 禁止普通数据库查询使用左模糊或全模糊扫描；确需全文检索时采用合适的全文索引或搜索系统。
- 重要 SQL 使用 `EXPLAIN`/`EXPLAIN ANALYZE` 和代表性数据检查访问类型、扫描行数、回表、排序和临时表；优先覆盖索引但不堆叠冗余索引。
- 深分页使用游标、键集分页或经验证的延迟关联方案；不要只凭固定行数阈值决定分库分表。

## SQL

- 查询字段必须显式列出，不使用 `SELECT *`；多表查询的列带明确别名，避免歧义。
- SQL 参数必须绑定，MyBatis 使用 `#{}`；`${}` 只能用于经过严格白名单约束且无法绑定的元数据，禁止拼接外部输入。
- 分页前的计数结果为零时直接返回；`COUNT(*)` 用于统计行数，聚合函数必须明确 `NULL` 语义并使用 `COALESCE` 等方式处理期望默认值。
- 控制 `IN` 集合、批量写入和单次返回规模；大批量操作分片并评估锁、日志、复制延迟和超时。
- 三张以上 Join、存储过程、外键和级联并非无条件禁止：默认按手册从严评审；若仓库允许，必须用容量、事务、一致性和可运维证据说明选择。
- 数据订正先以同条件查询确认范围，使用事务、备份/回滚方案和双人复核；生产修改必须单独确认。

## ORM、事务与迁移

- PO/Entity 属性类型与字段类型一致；布尔字段、下划线字段和枚举显式映射，不依赖可能变化的隐式转换。
- 查询结果使用类型明确的对象，不以无约束 `Map` 作为公共输出；更新只写允许修改的列并同步审计字段。
- 事务放在 Service 边界，明确传播、隔离、超时、锁顺序和异常回滚；不得滥用长事务。
- 使用仓库已有 Flyway、Liquibase 或等价迁移机制。已发布迁移不可修改；新增迁移必须可重复验证，并说明向前兼容、数据回填和回滚/前滚方案。
- 破坏性 DDL、大表变更、数据回填和索引创建必须评估锁表、磁盘、复制延迟及灰度顺序；生产执行前单独确认。
